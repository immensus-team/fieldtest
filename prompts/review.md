## 규칙

- 지금 디렉터리는 후보 commit이 checkout된 worktree다. 파일을 고치거나 commit하지 않는다.
  실행기가 검토 뒤에 worktree를 후보 commit으로 되돌리고, 바뀐 것이 있으면 이 검토를 무효로 한다.
- 검토 기준은 저장소의 작업 규칙 문서({{guideDocs}})에 있는 코드 리뷰 규칙을 따른다. 전체 diff를 읽는다. 구현자의 설명만 믿지 않는다.
- 실행기가 이미 돌린 검사({{allChecks}})는 다시 돌리지 않는다. 결과는 아래 "실행기 검사 결과"에
  있다. 확인에 필요한 spec만 돌린다.
- Playwright 테스트를 돌리기 전에 데모 서버를 멈춘다.

## 이번 작업에서 꼭 확인할 것

1. 티켓의 재현 절차를 기준 동작과 비교한다. 후보에서 결함이 실제로 사라졌는지 브라우저로 확인한다.
2. 후보를 깨뜨려 본다: 390px·1440px, light·dark, 키보드만으로 조작, 긴 입력, 빈 상태, 연속 클릭, 취소.
3. 요청 범위를 넘는 변경(리팩터링, 관계없는 파일 수정)이 있는지 본다.
4. 테스트가 결함을 실제로 검사하는지 본다. 항상 통과하는 assertion, 결함과 관계없는 assertion은 결함이다.
5. 같은 컴포넌트를 쓰는 다른 화면이 깨지지 않았는지 호출부를 따라가 확인한다.
6. 스크린샷 폴더({{shotsDir}})의 전후 화면이 티켓 설명과 맞는지 본다.
7. `kind`가 결함 종류 기준과 맞는지 본다. 입력·상태·키보드·포커스 이동·데이터 결함을 `visual`로
   분류했거나, 동작은 그대로이고 배치·겹침·넘침·잘림·색 같은 겉모습만 고친 결함을 `functional`로 분류해 재현
   테스트를 더했으면 차단 결함이다.
8. 재현 테스트가 맞는 자리에 있는지 본다. 로직은 unit test, 다시 지켜야 할 동작은 기존 spec에 더한 test,
   한 곳의 작은 결함은 `{{proofDir}}` spec이다. proof spec은 검토가 끝나면 빠지므로 PR에 남지 않는다.
   이 화면 한 곳의 focus·문구·작은 상호작용을 남는 테스트(기존 spec이나 새 spec 파일)로 더했거나, 같은 화면을
   다루는 spec이 있는데 `proof/` 밖에 새 spec 파일을 만들었거나, 남는 테스트가 문구 전체 비교·폭마다 같은 테스트
   반복·UI 라이브러리가 보장하는 동작 확인을 담으면 차단 결함이다.
9. 기능 결함이면 "실행기 검사 결과"의 base 실패 출력을 읽는다. 결함 assertion이 아니라 locator·import 오류로
   실패했다면 재현이 아니다. 이름이 없는 것 자체가 결함이면 locator 실패도 재현이다.

## 판정

- `verdict`는 차단 결함(`severity="blocking"`)이 하나라도 있으면 `fail`이다.
- 차단 결함: 결함이 남아 있음, 새 회귀, 테스트가 결함을 검사하지 않음, 범위 밖 변경, 저장소 규칙 위반,
  결함 분류가 틀림, 재현 테스트가 결함과 다른 이유로 base에서 실패함, 재현 테스트 위치 규칙 위반.
- 취향, 문체, 사소한 개선은 `minor`로만 적는다.
- 각 지적에 발생 조건, 기대·실제 동작, 근거(파일:줄 또는 실행 결과)를 쓴다. 추측으로 지적하지 않는다.
- 확인하지 못한 범위는 `notChecked`에 적는다.
- 지적마다 `severity`(`blocking`·`minor`), `title`, `condition`(발생 조건), `expected`, `actual`, `evidence`,
  `fix`를 채운다. `fix`는 이 결함을 없애는 구체적인 수정 방향 1~2문장이다. 구현자나 사람이 그대로 다음 시도의
  방향으로 쓸 수 있게 쓴다. 조건마다 방어 코드를 더하기보다 결함이 구조적으로 생기지 않는 방향을 먼저 고른다
  (예: 따로 저장한 상태 대신 원본 값에서 계산).
- 근거(파일:줄 또는 실행 결과)가 있는 차단 결함이 없으면 `pass`가 정상 결과다.
  지적할 것을 찾지 못한 것은 실패가 아니다.
- 확신이 없는 지적은 `blocking`으로 올리지 말고 `minor`나 `notChecked`에 쓴다.
