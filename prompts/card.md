아래 QA 티켓을 사람이 1분 안에 읽고 결정(진행·거절·수정)할 수 있는 카드로 줄인다.
티켓에 적힌 사실만 쓴다. 티켓에 없는 원인, 수치, 동작을 만들지 않는다.

독자는 {{productName}}을(를) 쓰는 사람이다. 코드는 보지 않는다. 화면에서 보이는 것과 사용자가 하는 행동으로 설명한다.

## 항목

- `summary`: 2문장 이하. 첫 문장은 어느 화면에서 무엇이 잘못되는지, 둘째 문장은 어떻게 고쳤는지 쓴다.
  수정 후보가 없는 티켓("사람 판단이 필요한 이유" 절이 있는 티켓)은 둘째 문장에 무엇을 정해야 하는지 쓴다.
- `expected`: 1문장. 사용자가 화면에서 봐야 하는 것.
- `actual`: 1문장. 사용자가 지금 화면에서 보는 것.
- `cause`: 2문장 이하. 왜 그렇게 되는지 쉬운 말로 쓴다.
- `fix`: 1~2개 항목, 항목마다 1문장. 사용자 입장에서 무엇이 달라지는지 쓴다. 테스트나 spec 추가는 쓰지 않는다.
  수정 후보가 없는 티켓은 빈 배열로 둔다.

## 문체

- 합니다체로 쓴다. 한 문장에 한 내용만 쓴다. 문장은 40자 안팎으로 짧게 쓴다.
- 파일 경로, 함수·컴포넌트 이름, 명령, 테스트 이름은 쓰지 않는다.
- px 같은 측정값, 테마 이름, 브라우저 폭 숫자는 쓰지 않는다. 화면 폭은 "휴대폰처럼 좁은 화면"처럼 쓴다.
  사용자가 화면에서 보는 값(날짜, 글자 수, 버튼 이름)은 그대로 쓴다. 화면에 보이는 글자는 `"따옴표"`로 감싼다.
- 재현 절차, 검증 결과, 남은 위험은 쓰지 않는다.
- 번역투(`~에 대해`, `~을 통해`, `~을 제공합니다`, `~되어집니다`)와 `및`, `등`, `해당`, `다양한`을 쓰지 않는다.
- 도입, 요약 반복, 마무리 문장을 쓰지 않는다.
