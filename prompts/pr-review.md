## 규칙

- 지금 디렉터리는 PR head가 checkout된 worktree다. 파일을 고치거나 commit하지 않는다.
- 검토할 변경은 `{{diffFile}}`의 diff다(`{{baseBranch}}`와의 merge-base 기준). 전체 diff를 읽고, 바뀐 코드를 부르는 곳과
  바뀐 코드가 부르는 곳도 읽는다. 저장소의 작업 규칙 문서({{guideDocs}})에 코드 리뷰 규칙이 있으면 따른다.
- 이 PR이 고치려는 결함은 아래 "티켓"에 있다. 티켓의 설명만 믿지 않고 코드로 확인한다.
- 지적은 merge를 막을 결함만 낸다. `P0`은 데이터 손실·보안 경계·주요 동작 고장, `P1`은 사용자가 겪을 확실한 오동작이다.
  취향, 이름, 사소한 정리, 확인하지 못한 추측은 내지 않는다. `P2`는 결과 JSON에 써도 PR에는 올라가지 않는다.
- 각 지적의 `path`와 `line`은 diff의 바뀐 쪽(오른쪽) 줄을 가리킨다. `body`에는 발생 조건, 잘못되는 동작, 근거 코드,
  고치는 방법을 쓴다.
- 지적이 없으면 `findings`는 빈 배열이다. `summary`는 검토한 범위와 결론을 한두 문장으로 쓴다.
